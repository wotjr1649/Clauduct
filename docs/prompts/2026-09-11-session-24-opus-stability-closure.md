## 확정된 완료 계약

감독하 개발과 무인 개발을 별도로 판정한다. 원인 미확정 UNSUPPORTED_EVENT가 남으면 안전 중단·데이터 보존·도구 중복 방지가 입증될 때 감독하 사용만 조건부 허용하고 무인은 HOLD다. 무인 PASS에는 계획→구현→독립 리뷰→테스트→로컬 커밋을 포함한 새 기능3개의 연속 주기를 하나의 실행에서 사용자 중간 개입이나 예기치 않은 오류 없이 완료한 증거가 필요하다. 이는 실제 인증 실행/비용 예산의 허가가 아니다.

## 수행 순서

1. 인계의 위험 행렬을 현행 소스·테스트·감사와 대조해 docs/remaining-verification.md의 오래된 상태/설정/진단 절차를 정리하라. 최신37건 PASS도 사용자 제공 종료 증거임을 명시해 반영하라. 완료/조건부/미검증/차단/범위밖을 분리하라.
2. API 최초 실패, native fallback, 취소/복구/완료 경합, 진단·자원 상한, 보안 경계에서 재현 가능한 공백을 조사하라. 관련 구현·테스트·리팩토링을 묶어 개선하고 통합 회귀로 검증하라. 기존 코드와 표준 기능을 재사용하고 결함·중복·측정 근거 없는 대규모 재구성은 하지 마라.
3. 의미 있는 묶음별로 diff와 secret 비노출을 검수하고 task-only 로컬 커밋하라. 모든 미세 단계에서 사용자 확인을 받지 말되, 실제 인증 실행·전역 변경·외부 쓰기·비용 확장이 필요한 지점은 해당 권한을 별도로 확인하라. guard 거부나 미실행 검사를 우회하거나 통과로 바꾸지 마라.
4. 로컬 작업을 먼저 완결한 뒤 변경 경로에만 필요한 실제 검증 계획을 작성하라. 제품 개발자 세션의 성공을 Clauduct native 검증으로 대신하지 마라. 기존 인증된 자동 native 실행 제한과 사용자 실행 경계를 유지하라. 원인 미확정 상태에서 무인3주기 PASS를 선언하지 마라.
5. 감독하 판정과 무인 판정, 커밋, Verified/Not verified/Blocked by, 모든 잔여 위험을 보고하라. 새로운 실사용 확인이 필요할 때만 실행 명령·범위·예상 증거·중단 조건이 있는 프롬프트를 제공하라. 사용자에게 동일 smoke 시험을 계속 반복시키지 마라.

기존 모델 직접 선택·직접 부모 model/effort 상속, 전역 설정 및 임의 --agents 차단을 유지하라. Claude 모델 전체 지원·app-server 전환·버전 pin·로그 원문 수집은 이번 목표가 아니다. 테스트 실패를 숨기거나 검증/보호를 약화하지 마라. 완벽함을 주장하는 대신 수용 기준별 실제 근거와 미확인을 남겨라.
