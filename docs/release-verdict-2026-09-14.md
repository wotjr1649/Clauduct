# HTTP/TCP·동적 링크 검사 제외 후 로컬 출하 판정

**후속 grilling 확정:** [Session-29 인계](prompts/2026-09-14-session-29-bounded-release-verdict.md)에 정상 Workflow의 프로세스 재시작 후 동일 세션 재개, 검증 방식, 3시간·추가64요청·입력400000/출력30000 예산과 변경 단위별 커밋을 정리했다. 아래는 기존 후보의 HOLD와 증거이며 새 구현의 완료 판정이 아니다. 두 주요 공백 외에도 기존 요구사항 표의 현재 적용 항목을 최신 증거와 대조한 뒤 전체 출하를 판정한다.

**최신 사용자 변경:** 동적 symlink/junction 실행 검사는 출하 판정에서 제외한다. F22의 신원·경로·재사용 검증 코드는 유지한다. 아래 F22 차단은 이전 판정 이력이며 더 이상 해당 동적 검사를 출하 선행 조건으로 삼지 않는다. 부모 직접 알림과 Workflow 재개의 필수성·해결 방향은 [후속 판단](release-priority-assessment-2026-09-14.md)에 정리했다. 직접 전달 방식과 안전한 결과 처리 요구를 구분하며, 정상 Workflow 재개는 현재 지원 약속의 개선 대상으로 유지한다.

현재 판정은 **HOLD — 전체 OK/PASS/FINAL은 미충족**이다. 승인된 독립 구현·회귀·실제 실행·복구·로컬 ZIP 제작을 마쳤으나, 아래 F12의 중첩 자식 결과/실패 처리와 F14의 정상 Workflow 재개를 완료로 표시할 근거가 없다. HTTP/TCP, 동적 링크 실행 검사, 정상 인증 갱신, 기본 400K/320K 압축 발동, 장기 시험은 이 HOLD의 이유에 포함하지 않는다. 목표를 완료로 변경하지 않았다.

원래 요구사항 표의 미지원 알림 경로와 동적 링크 검사 차단 이력은 보존한다. 최신 사용자 지시로 동적 링크 실행 검사를 제외하고, 직접 알림 방식과 필요한 결과 처리 기능을 구분했다. 추가 토큰을 쓰며 같은 실행을 반복하는 것으로 해결할 수 있는 상황이 아니다. 기존 거부 효과의 다른 경로 재현, 전역 보안 설정 변경, 제품 보호나 판정기의 완화, 실패 삭제는 수행하지 않았다. 위 표는 현재 공백과 제외 항목을 설명하며, F01~F23의 모든 조합을 이번에 새로 검증했다는 선언은 아니다. 실제 디스크 부족·전원 손실 등 수행하지 않은 환경 시험과 기존 요구사항 표의 그 밖의 미검증 이력도 보존한다.

과거의 실제 원장 registry 등록 차단도 별도 이력으로 남는다. 이번 실제 검사는 새 독립 fixture와 앞선 원장 숫자·미관측 예약을 연결한 유한 실행이며, 그 등록 효과를 재시도하지 않았다. 장기 관리기 운영 전체의 성공으로 확대하지 않는다. 모든 사용자 profile 조합·자연 발생 backend 장애·전원 손실 전반을 추가 출하 기준으로 만들지도 않았다.
