# Clauduct v0.4.2 — 릴리스 노트 초안

Windows x64용 Go V2 개발 검증을 마친 초안이다. 큰 요청이 겹칠 때의 메모리 사용을 측정하고,
본문을 읽기 전에 요청을 수용·대기·거부하는 정책을 추가했다. 태그·출하 검사·Release 발행은 아직 하지 않았다.

- **메모리 예산 안에서 요청을 받는다.** 프로세스별 예약 예산은 물리 메모리의 1/8, 최대 4 GiB다.
  생성·토큰 계수는 본문 크기로 예약량을 계산하며, 현재 여유 물리 메모리도 확인한다.
  예산이 잠시 부족하면 본문을 읽지 않고 최대 128건·30초까지 기다린다.
- **hook·이벤트 처리용 용량을 남긴다.** 작은 완료 알림도 transcript 복구로 이어질 수 있어 별도 용량과
  요청당 예약량을 적용한다. 이 경로의 대기는 최대 16건·0.5초다. 생성 요청이 제어용 용량을 빌려 쓰지는 않는다.
- **수용 거부의 원인을 구분한다.** 한 요청의 예산 초과, 대기열 포화, 대기 시간 초과, 메모리 조회 실패가
  각각 `MEMORY_*` 범주로 나온다. HTTP 429에 `X-Should-Retry: false`를 붙여 같은 대기가 자동으로 반복되지 않게 한다.
  여유가 생긴 뒤 다시 요청할 수 있다. 상태 파일의 `gateway.admission`에서 예약량과 대기 상태를 확인할 수 있다.
- **Claude Code 측정 기준을 2.1.282로 옮겼다.** 이전 2.1.281과 `--help`·사용 중인 plugin 타입은 같았다.
  설치 native fixture와 첫 출력 전후 7분 무출력 검사를 과금 없이 확인했고, 2.1.282의 실제 backend TUI도 통과했다.
- **다른 입력 출처의 제한을 명시했다.** 부모 대기 모드를 정하는 입력은 `composer`·`sdk`다.
  다른 세션의 메시지·예약 실행·채널 등 다른 출처만 받은 세션의 빈 응답 제어는
  [#130](https://github.com/wotjr1649/Clauduct/issues/130)(v0.4.3)에서 측정·수정한다.

정확한 예약 공식, 거부 범주와 지원 범위는 [호환성 문서의 v0.4.2 절](COMPATIBILITY.md#v042--메모리-수용-제어)이 소유한다.
기준 클라이언트는 Claude Code 2.1.282, Codex CLI 0.156.1이다. 모델 표와 위임 메뉴는 v0.4.1과 같다.

**자원 제한의 의미.** 예약량은 측정에 여유를 둔 추정이며 실제 RSS 상한이 아니다. 여러 프로세스의 예약을 합산하지 않는다.
물리 메모리 8 GiB 장비에서는 32 MiB 요청이 생성·계수 예산을 넘고, Windows가 보고하는 물리 메모리가 4 GiB 미만이면
제어 요청 한 건의 예약도 들어가지 않는다. 제어 대기 0.5초 뒤의 실제 처리 시간은 별도다.

v0.4.x 동안의 사본 전환과 설치·업데이트 방식은 v0.4.1과 같다([패키징 안내](PACKAGING.md)).
발행 뒤 되돌릴 때의 명령은 `install.ps1 -Tag v0.4.1`이다. Windows 전용이며 서명하지 않는다.

## 개발 검증 (2026-09-25)

개발 commit `bf68243364346876f950edede0bf4c3b397b083b`, Go 1.27.1 windows/amd64, CGO_ENABLED=0 기준이다.
검증 기록은 비공개로 관리하므로 결과만 적는다.

- gofmt, vet 3종(default·policy_evidence·runtime_evidence), build, 전체 test·race 각 20개 패키지, 문서 인용 검사 PASS.
  race는 CGO_ENABLED=1과 C 툴체인으로 실행했다.
- 메모리·예약 수명·본문 읽기 전 검사·취소·재시도 제어를 바꾸는 변이 9개 모두 테스트의 assertion으로 검출했다.
  build failure로 대신 판정한 항목은 없다.
- 실제 Claude Code 2.1.282와 로컬 backend로 새 메모리 거부를 확인했다. 요청 1회 뒤 자동 재시도 없이 끝났다.
- **실제 backend TUI 5회:** 생성 3회·압축 1회·취소 1회. 압축 뒤 내용 보존, transcript 순서, 복구·정상 종료·정리 PASS.
- **실제 backend SDK 5회:** 입력·`/clear`·자식 위임·완료 알림 PASS. 부모 `gpt-6-luna/max`, 자식 `clauduct-luna`의
  `effort: low`를 확인했고, 거부·끊김·실패는 0이었다. 종료 후 양쪽 메모리 예약량·실행 수·대기 수는 모두 0이었다.
  이 검증 바이너리만 ledger에 총 6회 상한을 더했고 제품의 admission 경로는 그대로 사용했다.
