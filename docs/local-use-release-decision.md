# 로컬 실사용 출하 판단 — 2026-09-14

현재 판정은 **로컬 실사용 출하 가능**이다. 사용자가 추가 개발 검증 비용을 줄이고 설정·출력 한도를 확인한 뒤 잔여 네 항목을 재평가하도록 요청한 데 따른 판단이다. 정상 native bypass 사용, 문서 기반 개발, 완료한 worker의 동일 저장 세션 Workflow 재개를 현재 사용 범위로 삼는다. 기존 전면 무인 안정성 판정은 HOLD 이력으로 유지하며 미실행 검사를 PASS로 바꾸거나 목표를 완료로 표시하지 않는다.

## 출력 한도는 서로 다른 세 값이다

| 값 | 확인 결과와 의미 |
|---|---|
| GPT 모델 최대 출력 | OpenAI 공식 모델 문서에서 gpt-5.6-sol과 gpt-5.6-luna 모두128000토큰. 한 응답의 모델 사양이며 실제 응답 길이나 이번 검증 예산이 아니다 |
| native 사용자 설정 | 이 머신의 C:\Users\js\.claude\settings.json에서 env.CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000을 제한적으로 읽어 확인. 다른 개인 설정 값은 복제하지 않았다 |
| 이번 추가 검증 출력 예산 | 전체30000토큰. 기존 fixture 기본32768과는 별도이며 원장·예약·엄격한 사전 검사 이력은 유지한다 |

근거: [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Claude 환경 변수](https://code.claude.com/docs/en/env-vars). 확인일2026-09-14.

64000은 파일에 설정된 값이다. native는 모델별 cap을 적용할 수 있고, 공식 문서상 인식하지 못한 gateway 모델의 기본값은32000이다. 따라서 개인 구성으로 실제 전송된 모든 요청의 최종 max_tokens가64000이었다고 주장하지 않는다. 이번 확인은 설정값·상속 경로·64000 입력의 adapter 처리 계약까지이며, 상한까지 채우는 실호출은 하지 않았다.

현재 Clauduct는 native 요청의 max_tokens를 outputLimit으로 받아 완료 응답의 usage.output_tokens와 대조한다. 구독 backend에 max_output_tokens를 보내지는 않는다. 따라서64000은 현재 제품에서 서버 생성량을 미리 중단시키는 보장이 아니다. 출력 한도 초과 응답은 기존 OUTPUT_TOKEN_LIMIT_EXCEEDED 검사 대상이며 그 보호는 유지한다. 문서를 읽는 입력이 많다고 같은 양의 출력이 생기는 것은 아니지만, 짧은 과제라는 이유만으로 누적30000의 수학적 보장을 주장하지도 않는다. 이번 재검토는 추가 실모델 호출0으로 진행했으며 일반 사용에 검증용30000 한도를 강제하지 않는다.

## 전역 설정과 프로젝트 로컬 설정

Clauduct launcher는 작업 시작 디렉터리(cwd)를 native에 전달하고 기본 설정 소스를 제한하지 않는다. 기본 전역 파일은 C:\Users\js\.claude\settings.json이며 CLAUDE_CONFIG_DIR이 지정되면 native가 그 디렉터리를 사용한다. 프로젝트의 .claude/settings.json과 .claude/settings.local.json도 native의 탐색·신뢰·우선순위 규칙에 따라 읽는다. 별도의 Clauduct JSON 병합기를 추가할 필요가 없다.

일반적인 동일 키의 우선순위는 managed 정책, 명령행 설정, 프로젝트 local, 프로젝트 shared, 사용자 전역 순서다. native가 --settings JSON과 하위 설정을 병합하므로 Clauduct가 지정하지 않은 output·permissions 값은 하위 설정에서 유지된다. 현재 사용자 루트와 구현 worktree에는 위 두 프로젝트 설정 파일이 모두 없다. 저장소 하위 디렉터리·worktree에서는 native의 저장소 루트 탐색 규칙이 적용된다. [공식 설정 우선순위](https://code.claude.com/docs/en/settings).

Clauduct가 소유하는 모델 선택·gateway·컨텍스트 정책·복구 관련 설정과 hook은 현재 구현의 overlay로 유지한다. 모든 개인 설정을 그대로 적용한다는 뜻은 아니다. 이번 로컬 검사는 cwd 보존, 설정 소스 유지, permissions/output 키를 overlay로 덮지 않음, max_tokens=64000의 완료 사용량 검사 전달을 확인했다. native-protocol의 기존 출력 초과 거부 검사도 통과했다. 전역·프로젝트 파일 자체를 변경하지 않았다.

## 기존 HOLD 네 항목의 재분류

네 항목 모두가 기술적으로 실사용에서만 검증 가능한 것은 아니다. 출하 판단에 필요한 증거와 비용을 기준으로 아래와 같이 구분한다. 기존 실패나 NOT_RUN 원자료는 그대로 남긴다.

| 항목 | 확인한 사실 | 이번 로컬 출하 판단 / 운영 관찰 |
|---|---|---|
| 새 실모델 호출의 생성 전30000 제한 | 모델128000·native64000·검증예산30000은 서로 다르다. 현재 전송은 완료 사용량 검사이며 기존 실제 두 모델 개발·라우팅 증거가 있다 | 검증 비용 제한을 제품 결함으로 취급하지 않는다. 추가 실모델 시험을 중단하고 기존 실호출과 변경 경로의 공개 native 증거를 재사용한다. 사전 예산 보장 없는 자동 검증은 계속 거부한다 |
| 압축·재시작·자식 실패 결합 | 개별 압축 계약, 실패 보존, 재개 및 파일 효과 검사는 있다. 결합 사건 자체는 NOT_RUN이다 | 실사용 관찰로 이관한다. 복합 사건 무손실을 보증하지 않는다. 실제 발생 시 같은 저장 세션·기록·파일 효과를 확인하고 원래 과제를 마감했는지를 기록한다 |
| 캐시 실제 적중 및 현재 bypass UI/hooks/plugin 통합 | 기존 캐시 관측은0. 핵심 native/launcher/hook/MCP 계약은 검증됐으나 개인 구성 전체는 실행하지 않았다 | 캐시 적중은 성능·비용 관찰 사항으로 둔다. 개인 hook/plugin의 실제 동작은 사용 중 관찰한다. 적중이나 임의 개인 구성 호환성을 제품 필수 성공 조건으로 확대하지 않는다 |
| 활성 Workflow worker의 중복 재개 | 정확한 반환 경로를 native가 먼저 거부했고 중복 자식·파일 효과0, 원래 worker 취소·종료를 확인했다 | 알려진 native 제한으로 문서화한다. 같은 작업이 실행 중이면 완료 또는 취소·종료 후 동일 저장 세션을 재개한다. 종료 후 정상 재개는 두 모델의 공개 native 시험에서 저장 결과 재사용·실패 단계 재실행·원래 파일 작업 완료로 입증했다. 경로 거부 우회는 지원하지 않는다 |

운영에서 결과 소실·파일 효과 중복·잘못된 부모/세션 연결이 관측되면 해당 사용 경로를 보류하고 그 사건을 재현 근거로 삼는다. 단순 캐시 미적중이나 알려진 활성 worker 재개 거부를 새로운 전면 개발 검증 루프로 바꾸지 않는다.
